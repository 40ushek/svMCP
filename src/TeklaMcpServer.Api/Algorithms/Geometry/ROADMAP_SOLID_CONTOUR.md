# Roadmap: контур детали по solid-сечению

## Назначение

Получать **реальный контур детали** (с учётом булевых обрезок / cut), а не исходный
заданный контур. Нужен для простановки контурных размеров (углы, радиусы, диагонали)
по фактической геометрии — для **плит и балок**.

Проблема, ради которой это делается:
- `ContourPlate.Contour.ContourPoints` и polycurve возвращают **исходный** контур,
  заданный при создании плиты. Булевы операции (Boolean cut, вырез телом) **не меняют**
  этот контур — они режут solid. Поэтому углы, посчитанные по `Contour.ContourPoints`,
  на обрезанных деталях **неправильные** (полигон не соответствует видимой геометрии).

Источник паттерна (рабочий, проверенный): `sv_tekla_lib` →
`Geometry/ContourPlateUtils.GetContourPlatePolygons` и `Geometry/IntersectionHelper`.

## Реализовано ✅

Два самостоятельных хелпера в `Algorithms/Geometry/` (коммит `15ecbfb`):

- **`SolidSectionContourHelper`** — контур через сечение solid плоскостью
  (`Solid.IntersectAllFaces(p1,p2,p3)`). Учитывает булевы обрезки.
  - `GetSectionContour(part, zOffset)` / `GetSectionPolygons(...)` — сечение по СК **детали**.
  - `GetViewPlaneSectionPolygons(part)` — сечение плоскостью, **параллельной текущей рабочей
    плоскости** (XY), на Z = центр solid по Z. Для использования, когда work plane уже
    выставлен в СК вида.
  - `IntersectToPolygons(solid, p1, p2, p3)` — низкоуровневый.
- **`SolidFaceContourHelper`** — контур через лицевую грань (`GetFaceEnumerator` → loop →
  вершины). Запасной путь; для булен менее надёжен, чем сечение.

Оба возвращают `List<Point>` (внешний контур) + отдельно openings; в координатах,
заданных текущей рабочей плоскостью.

Внешний контур выбирается **по максимальной площади** (shoelace), а не по индексу 0 —
Tekla не гарантирует порядок полигонов от `IntersectAllFaces`. Остальные полигоны
трактуются как отверстия.

## Канонический алгоритм (для контурных размеров)

Подтверждён пользователем:

1. Взять `View`, поставить рабочую плоскость в **СК вида**:
   `WorkPlaneHandler.SetCurrentTransformationPlane(new TransformationPlane(view.ViewCoordinateSystem))`.
2. Получить `solid` детали — он теперь в координатах вида.
3. Секущая плоскость — **параллельна плоскости СК вида** (XY вида), на глубине
   Z = центр solid по Z (`(MinimumPoint.Z + MaximumPoint.Z)/2`).
   Важно: плоскость берётся от **вида**, не от детали — поэтому работает и для балок,
   и для плит (на чертеже видим проекцию на плоскость вида).
4. `IntersectAllFaces` → внешний контур в координатах вида.
5. Дальше — существующая логика углов (`DimensionAnglePlacementHelper`): соседи, flip,
   right-angle, вставка `AngleDimension`.

Для шага 2-4 предназначен `GetViewPlaneSectionPolygons(part)`.

## Следующий этап — подключение к `place_contour_angle_dimensions`

Файл: `Drawing/Dimensions/TeklaDrawingDimensionsApi.Commands.cs`.

Критичные требования (подтверждены):
1. **Не использовать** `ContourPlate.Contour.ContourPoints` для деталей с boolean cut —
   он отдаёт исходный контур до обрезки.
2. Источник точек: `SolidSectionContourHelper.GetViewPlaneSectionPolygons(part).contour`
   (work plane уже в СК вида).
3. Поиск детали: `is ContourPlate` → `is Part` (принимать **балки тоже**).
4. **Flip / winding** — отдельно проверить на реальном чертеже: направление обхода
   контура из сечения (CW/CCW) влияет на выбор «соседей» и внутренний угол.
   ⚠️ Самый тонкий момент.
5. **Внешний контур** — выбирать явно по площади (уже реализовано в хелпере), не
   полагаться на первый polygon от Tekla.

## Инварианты (не нарушать)

- Логика углов централизована в `DimensionAnglePlacementHelper` — **не дублировать**.
- Идемпотентность `place_contour_angle_dimensions` (удаление старых `AngleDimension`
  перед простановкой) сохраняется.
- Хелперы остаются переиспользуемыми и нейтральными к контексту (model/view —
  зависит от выставленной рабочей плоскости вызывающим кодом).
- Внешний контур определяется по площади, не по порядку полигонов от Tekla.

## Риски / открытые вопросы

- Сечение балки: на глубине центра solid профиль может дать «не тот» контур, если
  деталь ориентирована нестандартно к виду — проверить на реальном чертеже балки.
- Несколько деталей в виде: сейчас берётся первая. Для multi-part видов нужна стратегия
  (по выделению / по всем / по самой большой).
- Отверстия (openings) пока в углах не используются — только внешний контур.

## Проверка перед внедрением

Сначала debug-командой (например `get_part_section_contour viewId modelId`) вывести
контур из сечения в СК вида для проблемного чертежа (балка, плита с булевым срезом),
убедиться что полигон правильный — **потом** менять `place_contour_angle_dimensions`.
