# Project Drafting Rules

## Проверка кода перед ответом

- Никогда не отвечать на вопросы о коде, архитектуре, инструментах MCP или поведении этого проекта без предварительной проверки соответствующего актуального кода.
- Перед объяснением причины, описанием возможностей или предложением решения прочитать реализацию и относящиеся к вопросу контракты. Не подменять проверку предположениями, общими рекомендациями или памятью о прежних версиях.
- В ответе опираться на проверенные места кода и указывать файлы, когда это помогает подтвердить вывод. Если код недоступен или не даёт ответа, прямо сказать, что вывод не установлен.
- Вопрос или обсуждение решения не является разрешением менять код; вносить изменения только по запросу пользователя.

- Диагональные размеры: это размеры между крайними дальними точками сборки; используются для контроля геометрии.
- Для layout-таблиц канонический источник видимых границ: `Segment.Primitives[0/2]` из presentation model.
- Контракт: `Primitives[0]` = min-corner marker, `Primitives[2]` = max-corner marker.
- Не заменять marker-based path общей аккумуляцией примитивов без явного доказательства, что canvas markers недоступны для конкретного runtime/template.

## Размерные точки

- `points[0]` задаёт истинную начальную точку размерной цепочки для горизонтальных и вертикальных цепочек.
- При чтении Tekla нормализует порядок точек для отображения, поэтому JSON-порядок не подтверждает начальную точку напрямую.
- Для одной простой непрерывной цепочки истинное начало можно восстановить по связности `Segment.StartPoint/EndPoint` для обеих осей.
- Для разветвлённой, разорванной или неоднозначной цепочки начало нельзя угадывать — такую цепочку нужно пометить как требующую проверки.
